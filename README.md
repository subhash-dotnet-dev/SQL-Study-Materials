## 🎯 Why This Repository Exists

I created this repository to document my SQL learning journey in a structured and transparent way. Rather than keeping learning limited to classroom notes, I organized concepts into daily folders containing explanations, quick revision notes, interview questions, and SQL practice.

The goal is to build SQL fundamentals, understand SQL Server, practice T-SQL, improve query-writing ability, develop database-design awareness, prepare for backend development and technical interviews, and maintain a visible record of continuous learning.

## Learning Method

```text
LEARN → UNDERSTAND → WRITE → EXECUTE → TEST → DEBUG → DOCUMENT → REVISE → IMPROVE
```

This repository documents the actual learning process—not only successful queries, but also experimentation, debugging, corrections, revision, and improvement.

## 💻 Hands-On Practice

Practice includes writing and executing SQL queries in SQL Server; testing outputs; working with tables; filtering and joining records; aggregating data; building subqueries and CTEs; practicing window functions and T-SQL constructs; debugging syntax and logic errors; and revising incorrect approaches.

> “Don't just read the query. Write it, execute it, understand the output, and investigate the mistake.”

### SQL query thinking

```text
WHAT DATA DO I NEED?
        ↓
WHERE IS THE DATA?
        ↓
WHICH TABLES ARE INVOLVED? → HOW ARE THEY RELATED?
        ↓
WHAT CONDITIONS ARE REQUIRED?
        ↓
DO I NEED GROUPING OR AGGREGATION?
        ↓
DO I NEED A JOIN OR A SUBQUERY / CTE?
        ↓
HOW WILL I VALIDATE THE RESULT?
```

  ↓ ADO.NET / Entity Framework Core
  ↓ SQL Server

SQL is being learned as a foundation for backend development rather than as an isolated subject. This knowledge supports data access, CRUD operations, API development, transactions, data validation, relational design, stored-procedure integration, and backend debugging.

### Database development mindset

```text
APPLICATION → API → BUSINESS LOGIC → DATA ACCESS → SQL → DATABASE
                                                   ↓
                              TABLES → RELATIONSHIPS → DATA INTEGRITY
```

Understanding this flow helps connect application code with the databases that store, validate, and relate its data.
